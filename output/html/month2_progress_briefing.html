The thesis follows a gate system: each month's methods are only allowed to start once the previous gate has both technical evidence (code that runs and reproduces) and a passed conceptual review (the student can explain what the numbers mean, not just that the code executed). Month 1 — centralized baselines (closed 2026-08-16)

Before any federated method, the project needed a ceiling: what does a single model trained on all the data, with no client structure at all, actually achieve? Four models were trained on MNIST and CIFAR-10, each stricter than the last.

Logistic regression established the floor (a model that can only draw straight lines between classes). A small multilayer perceptron came next, showing what a hidden layer of learned features buys over that floor. A convolutional network followed, exploiting the fact that nearby pixels form shapes rather than being independent numbers — on MNIST it pushed error down further, and on the harder, more varied CIFAR-10 images it produced a realistic reference for how much room the "easy" MNIST numbers were leaving on the table.

All four were reviewed against the original literature as a plausibility check (not a claim of exact replication, since architectures, splits, and training budgets differ), and the student passed a ten-question review demonstrating understanding of forward propagation, loss, backpropagation, and why validation and test sets must stay separate.

Month 2, Weeks 5–7 — FedAvg written by hand

Federated Averaging (McMahan et al., 2017) was implemented from scratch before any framework was introduced, so every line responsible for the result could be inspected directly rather than trusted as a black box.

The mechanism itself is simple to state: each round, selected clients receive a copy of the current global model, train locally on their own data for a fixed number of epochs, and send their updated weights back. The server then combines those weights, giving each client's update a weight equal to its share of the total training examples used that round — a client with more data pulls the average further toward its update. That weighted average becomes the next global model.

Thirteen synthetic tests verify this mechanism in isolation: correct weighting on unequal client sizes, no accidental sharing of tensor memory between local and global models, exact reproducibility across repeated runs, and correct rejection of invalid updates. Only after those passed was Flower (an established FL framework, version 1.30.0, the newest release still compatible with this project's Python 3.10 environment) introduced — used strictly as an independent check, never as the code path that produces results. Flower's own aggregation function was run side by side with the hand-written one on the same inputs and matched exactly, including a hand-verified example: two clients with 20 and 80 examples returning weights 1.0 and 3.0 average to 2.6, not the unweighted 2.0.

Month 2, Week 8 — the first real result

With the mechanism verified on synthetic data, the first genuine question could be asked: on real MNIST data, split across several clients, how does hand-written FedAvg compare to an ordinary centralized model trained on the same data?

Five clients received equal-sized, independently and identically distributed (IID) shards of the 51,000-image MNIST training set. All five participated in every one of five communication rounds, training for one local epoch each. The centralized baseline used the same starting weights, the same optimizer settings, and five full passes over the same data — a matched-exposure comparison, meaning both paths see the same total number of training examples (255,000), even though centralized training follows one continuous trajectory while FedAvg alternates five separate local trajectories with an averaging step in between.

This is reported plainly as a negative result for FedAvg in this configuration — the plan's own risk-management guidance is explicit that a thesis does not need to show every method beating every baseline, only that results are measured and interpreted honestly. It is correct to say FedAvg underperformed here; it is not correct to generalize from one seed, one client count, and one IID split to a claim that centralized training is always better. FedAvg's own validation accuracy rose across all five rounds (10.4% → 84.7% → 88.1% → 89.3% → 89.9% → 90.3%), showing the method is learning as expected, just converging to a lower point under this specific budget.

Gate 2 — closed 2026-09-07

Passing Gate 2 required more than a working experiment: explaining what the Week 8 result means, then deliberately changing it in two controlled ways and interpreting what changes and what doesn't.

Part A asked eight conceptual questions — tracing exactly where local training changes weights versus where server aggregation does, explaining why every client must start a round from the same global model, and correctly separating the negative accuracy result from any claim about FedAvg's general superiority or inferiority. All eight were answered correctly and reviewed as passing on 2026-09-06.

Part B required two further experiments, proposed and predicted before either was run: doubling the client count to K=10 while holding everything else fixed, and doubling local epochs to E=2 while scaling the centralized baseline's epoch count to match (so the exposure comparison stayed fair). Every predicted number — examples per client, optimizer-step totals, training-example exposures, communication bytes — matched the executed result exactly.

Doubling the client count (K=10) widened FedAvg's gap to centralized — more, smaller IID shards produced a lower-utility model in this run, at double the communication cost (40.7 MB vs. 20.4 MB) for the same number of optimizer steps. Doubling local epochs (E=2) raised both methods' absolute accuracy (centralized +1.4pp, FedAvg +1.3pp) without changing communication at all, since transfer frequency depends on client count and rounds, not local epochs — but it also left the relative gap to centralized essentially unchanged. Both results are reported as measured, from one seed and one architecture, not as general claims about client count or local-epoch tuning.
